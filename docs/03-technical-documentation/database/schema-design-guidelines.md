## 1. Engine, Compatibility & Schema Organization

| Concern | Approved Standard | Notes |
|---|---|---|
| **Production Engine** | **Microsoft SQL Server 2022** | Authoritative production relational database target (`D-DB-01`). |
| **Local Development Engine** | **Microsoft SQL Server 2025 Developer (`17.0.1000.7`)** | Local `MSSQLSERVER` instance; **must** use database compatibility level **`160`** (SQL Server 2022) when created. SQL Server 2025-only features, syntax, or data types are **prohibited**. |
| **Database & Schema** | **One shared MetroLMS database**, **`dbo` schema** | `G-02` (`OWNER-APPROVED`, `2026-11-16`). Per-Feature SQL Server schemas and Microservices are prohibited. |
| **Active Scope** | **`54` active entities / `305` physical columns** | `InPersonAttendanceRecord` (`Domain 16`) remains **`DEFERRED`**. |

## 2. Primary Keys, Foreign Keys & Referential Actions

- **Primary Keys (`54` total):**
  - `50` `BIGINT IDENTITY(1,1)` surrogate PKs (`2` early-approved + `48` `OR-DB-01` `2026-11-16`).
  - `3` String PKs: `RolePolicy.role_key` (`NVARCHAR(32)`), `ServerSession.session_key` (`NVARCHAR(40)`), `DepartmentTrack.department_code` (`NVARCHAR(64)`, Option A — no surrogate `id`).
  - `1` `UNIQUEIDENTIFIER` PK: `PendingApprovalRequest.id` (`WP55-PT-01`).
- **Foreign Keys (`84` constraints across `85` distinct FK columns):**
  - `84/84` integer FK type matches (`BIGINT` → `BIGINT`), plus `User.role` (`NVARCHAR(32)` → `RolePolicy.role_key`).
  - `UserJobTitle` holds `2` composite FKs sharing `department_id`: `(user_id, department_id)` → `UserOrganizationalDepartment` and `(department_id, job_title_id)` → `DepartmentJobTitle`.
  - **Referential Action:** **`ON DELETE NO ACTION`** on **all `84` FKs** to prevent SQL Server multiple-cascade-path Error `1785` and enforce `D-01` / `D-03` atomic service-layer deletion.

## 3. Physical Data Type & Collation Standards

| SQL Server Type | Count / Scope | Standard Usage |
|---|---|---|
| `BIGINT` | `50` PKs + `82` FK cols + `MediaAsset.size_bytes` | Surrogate keys and non-negative byte size (`CHECK (size_bytes >= 0)`). |
| `UNIQUEIDENTIFIER` | `1` PK (`PendingApprovalRequest.id`) | UUIDv4 generated by application/ORM. |
| `NVARCHAR(n)` / `NVARCHAR(MAX)` | `101` active physical string fields | Governed by `OR-DB-02` lengths (`14` to `2048` and `MAX`). |
| `DATETIMEOFFSET(7)` | `38` timestamp fields | UTC (`+00:00`) canonical storage (`D-05`, `DD-PROSE-01`, `DD-PROSE-02`). |
| `DATE` | `4` date-only fields | `User.appointment_date`, `date_of_birth`, `service_end_date`; `HistoricalServiceTrainingRecord.completion_date`. |
| `INT` | `11` integer fields | Counts, durations, sort orders, `interval_days`, telemetry counters. |
| `BIT` | `12` boolean fields | Flags (`is_active`, `is_sealed`, `is_completed`, `is_enabled`, etc.). |
| `DECIMAL(5,2)` | `1` field (`QuizDefinition.passing_score`) | Exact percentage precision `0.00`–`100.00`. |
| `BINARY(32)` / `VARBINARY(32)` | `2` hash fields | `CertificateRecord.verification_token_hash` (`BINARY(32)`), `GroupQrCode.token_hash` (`VARBINARY(32)`). |

- **Collation Policy (`OR-DB-04`):** General database/column collation is **`Arabic_100_CI_AS`** (`OWNER-APPROVED`, `2026-11-16`), preserving column-level **`Arabic_100_BIN2`** exceptions such as `User.phone_e164` ASCII digit/prefix `CHECK` comparison.

## 4. Constraints, Defaults, Nullability & `45`-Entry Index Baseline

- **Defaults (`16` total):** `ScheduledJob.is_enabled DEFAULT 1` + `15` `OR-DB-01` defaults (emitted at both ORM and SQL Server `DEFAULT` layers via `default=` + `db_default=`).
- **Nullability:** `23` `OR-DB-01` nullable columns across `12` groups + explicitly documented `NOT NULL` columns in `data-dictionary.md` §11.5.
- **`CHECK` Constraints (`52` individual SQL Server `CHECK`s):** `38` domain/enum/range/XOR/date checks + `4` `LessonProgress` telemetry `>= 0` checks + `10` non-empty text `LTRIM(RTRIM(col)) <> N''` checks (`User.phone_e164` uses `COLLATE Arabic_100_BIN2` + `DATALENGTH = 26` + `LEN = 13`).
- **`ISJSON()` Constraints (`9` JSON fields):** `5` `ISJSON(..., ARRAY)`, `3` `ISJSON(..., OBJECT)`, `1` untyped `ISJSON(...)` (`ScheduledJobRun.details_json`).
- **`OR-DB-03` Index Baseline (`45` entries):**
  - `4` Filtered `UNIQUE` Indexes: `User(role) WHERE role = 'developer'`, `User(email) WHERE email IS NOT NULL`, `GroupJoinRequest(training_group_id, user_id) WHERE request_status = 'Pending'`, `CertificateRecord(course_attempt_id) WHERE course_attempt_id IS NOT NULL`.
  - `36` Ordinary `UNIQUE` constraints/indexes (`15` C1 + `8` C2 + `13` C3).
  - `5` Non-Unique lookup indexes: `ServerSession(expire_date)`, `ServerSession(user_id)`, `PendingApprovalRequest(target_entity_type, target_entity_id)`, `MediaAsset(sha256_checksum)`, `DelegatedAuthority(user_id, capability_key)`.
- **Concurrency:** Use Read Committed Snapshot Isolation (`RCSI`) and `select_for_update()` inside `@transaction.atomic()` for critical state transitions (e.g., `INV-DOM10-12` group renewal, `D-01` deletion).
